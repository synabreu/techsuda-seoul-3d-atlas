# 검증 계획

## 1. 목적

Seoul 3D Atlas의 기능, 데이터 무결성, 렌더링, 배포 가능성을 완료 전에 확인한다.

## 2. 데이터 검증

### 서울 자치구

- 예상 개수: 25
- 실제 개수 기록
- 누락 여부 확인
- 중복 여부 확인

### 건물

기록:

- 처리된 총 건물 수
- 원본 레코드 수
- 제외된 레코드 수
- 제외 이유

### 바이너리 파일

검증:

1. 파일 로드 가능
2. 메타데이터 파싱 가능
3. 메타데이터 record count와 디코딩 결과 일치
4. 고정 길이 형식이라면 예상 byte length와 실제 크기 일치
5. 잘린 파일 또는 잘못된 파일 입력 시 검증 실패

## 4. 랜드마크 검증

14개 랜드마크 각각 확인:

- 데이터 존재
- 위치 정상
- 카메라 이동 성공
- 카메라 충돌 없음
- 체류 후 다음 위치 이동
- 마지막 랜드마크 이후 상태 정상
- 수동 제어 복귀 가능

## 5. 시각 검증

대표 카메라 위치에서 확인:

- 한강 가시성
- 산악 지형 가시성
- 건물이 수면을 가리지 않는가
- terrain이 수면을 가리지 않는가
- 건물 높이가 비정상적으로 과장되지 않았는가
- 주요 랜드마크 위치가 상식적으로 맞는가
- 자치구 경계가 읽히는가

## 6. 모바일 검증

가능한 실제 모바일 또는 모바일 에뮬레이션에서 확인:

- UI 겹침
- 터치 제스처
- 확대/축소
- 패닝
- 회전
- 화면 방향 변경
- 렌더링 예산 적용 여부

## 7. 프로덕션 빌드

확인:

- 빌드 명령 성공
- 정적 산출물 생성
- 필수 데이터 파일 포함
- 경로 오류 없음
- 콘솔 치명적 오류 없음

실제 테스트 결과만 사용한다.
