# 제품 요구사항 — Seoul 3D Atlas

## 1. 제품 목적

사용자가 웹 브라우저에서 서울 전체를 하나의 미니어처 3D 공간처럼 탐색할 수 있도록 한다.

사용자는 설치 없이 다음 동작을 수행할 수 있어야 한다.

- 회전
- 확대
- 축소
- 패닝
- 주요 랜드마크 자동 탐색
- 낮/노을/야경 전환
- 자치구 경계 표시

## 2. 지도 범위

반드시 포함한다.

- 서울 25개 자치구
- 서울 전체 건물
- 한강
- 주요 수계
- 주요 도로
- 서울 주변 산악 지형
- 14개 주요 랜드마크

25개 자치구는 프로그램적으로 개수를 검증한다.

## 3. 건물 데이터

가능한 한 원본 데이터의 다음 정보를 유지한다.

- 위치
- footprint
- 높이

높이 정보가 없는 경우 추정값을 사용할 수 있다.

추정 높이는 실제 측정 높이처럼 표시하지 않는다.

층수를 사용하여 높이를 추정하는 경우 계산식을 문서화한다.

## 4. 자치구 경계

사용자는 서울 25개 자치구 경계를 켜고 끌 수 있어야 한다.

## 5. 랜드마크

14개 주요 랜드마크를 선정한다.

각 랜드마크는 다음을 제공한다.

- 이름
- 지도 위치
- 카메라 목표점
- 자동 비행용 카메라 위치

첫 방문자가 별도 조작 없이 서울 주요 지역을 볼 수 있도록 순차 자동 비행 기능을 제공한다.

## 6. 환경 모드

최소 다음 모드를 제공한다.

- 낮
- 노을
- 야경

## 7. 입력

### 데스크톱

- 마우스 회전
- 휠 확대/축소
- 마우스 패닝

### 모바일

- 터치 회전
- 핀치 확대/축소
- 터치 이동

## 8. 시각적 구분

다음 요소는 서로 쉽게 구분되어야 한다.

- 한강
- 산
- 도로
- 건물
- 자치구 경계

한강은 건물이나 지형 아래로 숨지 않아야 한다.

## 9. 높이 과장

가독성을 위해 지형 또는 건물 높이를 과장할 수 있다.

과장을 사용할 경우:

- 배율 기록
- 이유 설명
- 웹사이트 정보 패널 공개
- README 공개

## 10. 데이터 출처 공개

웹사이트와 README에 다음을 기록한다.

- 데이터 출처
- URL
- 스냅샷 또는 조회 날짜
- 라이선스
- 전처리 여부

## 11. 정적 웹사이트

최종 애플리케이션은 정적 배포가 가능한 구조로 만든다.

## 12. 완료 기준

- 25개 자치구 검증
- 처리 건물 수 확인
- 건물 바이너리 검증
- 회전/확대/축소/패닝 테스트
- 모바일 입력 테스트
- 14개 랜드마크 자동 비행 테스트
- 낮/노을/야경 테스트
- 한강 시각 검증
- 주요 지형 시각 검증
- 데이터 출처 및 라이선스 공개
- 프로덕션 빌드 성공
