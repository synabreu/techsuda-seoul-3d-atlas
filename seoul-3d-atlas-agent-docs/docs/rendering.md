# 렌더링 및 성능 설계

## 1. 목표

수십만 개 건물을 브라우저에서 표현하면서도 서울 전체를 탐색할 수 있도록 렌더링 비용을 제어한다.

## 2. Three.js 기본 원칙

- 공유 Geometry 사용
- 공유 Material 사용
- `InstancedMesh` 우선 검토
- 가능한 경우 배치 렌더링
- 불필요한 객체 생성 최소화
- 장면 계층 구조 단순화

## 3. 건물 렌더링

피해야 할 구조:

```text
수십만 개 건물
→ 동일 수의 독립 heavyweight Mesh
```

권장 구조:

```text
건물 그룹
→ 공유 geometry/material
→ InstancedMesh 또는 batches
```

## 4. LOD 및 가시성

카메라 거리와 줌 수준에 따라 다음을 조정할 수 있다.

- 원거리 건물 수
- 세부 geometry
- 라벨
- 그림자
- 환경 효과

## 5. 모바일 렌더링 예산

모바일은 데스크톱과 동일한 렌더링 설정을 강제하지 않는다.

가능한 조정:

- devicePixelRatio 상한
- shadow map 크기 감소
- 그림자 비활성화
- 원거리 건물 표시 수 감소
- 라벨 수 감소
- 후처리 효과 감소

## 6. 수면

한강은 별도의 명확한 수면 레이어로 유지한다.

검증:

- 건물이 수면 위에 비정상적으로 생성되지 않는가
- terrain mesh가 수면을 가리지 않는가
- 수면 높이가 주변 geometry와 충돌하지 않는가

## 7. 지형

지형 과장을 사용할 수 있다.

사용 시 기록:

- 배율
- 적용 범위
- 사용 이유

## 8. 환경 모드

### 낮
- 밝은 환경광
- 명확한 지형과 건물 구분

### 노을
- 낮은 태양 고도
- 따뜻한 조명
- 과도한 그림자로 지형이 사라지지 않게 조정

### 야경
- 건물 윤곽 유지
- 한강 가시성 유지
- 중요 도로 및 랜드마크 구분

## 9. 성능 측정

FPS를 보고할 경우 실제 장치에서 측정한다.

기록:

- 장치
- GPU
- 브라우저
- 화면 해상도
- DPR
- 카메라 위치
- 건물 표시 수
- 측정 방법

측정하지 않았다면 구현한 최적화만 설명한다.
