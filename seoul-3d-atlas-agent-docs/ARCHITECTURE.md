# ARCHITECTURE.md — Seoul 3D Atlas 시스템 구조

## 1. 개요

Seoul 3D Atlas는 브라우저에서 실행되는 정적 Three.js 기반 3D 지도 애플리케이션이다.

주요 구조는 다음 다섯 계층으로 나눈다.

1. 원본 데이터
2. 전처리 파이프라인
3. 정적 배포 데이터
4. 브라우저 렌더링 엔진
5. 사용자 인터페이스

## 2. 전체 데이터 흐름

```text
공개 원본 데이터
    ↓
전처리 스크립트
    ↓
좌표 변환 / 필터링 / 단순화 / 높이 처리
    ↓
압축 이진 건물 데이터 + 메타데이터
    ↓
정적 웹 자산
    ↓
브라우저 로드
    ↓
Three.js Scene
    ↓
InstancedMesh / Terrain / Water / Roads / Boundaries
    ↓
사용자 상호작용
```

## 3. 데이터 계층

### 건물

OpenStreetMap 계열 데이터를 기본으로 한다.

보존 대상:
- 위치
- footprint
- 원본 높이
- 층수
- 건물 유형
- 원본 식별자(가능한 경우)

높이가 없는 경우 추정값을 사용할 수 있으나 추정 여부를 구분한다.

### 도로

도시는 줌 수준과 성능 목표에 맞춰 도로 geometry를 단순화할 수 있다.

### 수계

한강과 주요 수계는 건물 및 지형보다 시각적 우선순위를 높게 둔다.

건물 또는 terrain mesh가 수면을 가리는 오류가 발생하지 않도록 별도 검증한다.

### 지형

공개 표고 데이터에서 terrain mesh를 생성한다.

도시 전체 보기에서 지형이 지나치게 평평하게 보일 경우 시각적 과장을 사용할 수 있다.

## 4. 전처리 계층

전처리 단계:

- 대상 지역 필터링
- 좌표계 변환
- footprint 단순화
- 높이 계산
- 건물 속성 정규화
- 이진 데이터 생성
- 메타데이터 생성
- 무결성 검증

전처리는 반복 실행 가능해야 한다.

## 5. 이진 데이터 구조

가능하면 건물 데이터는 고정 길이 또는 명시적 디코딩 규칙을 가진 압축 이진 형식을 사용한다.

메타데이터 예시는 참고용이며 실제 값으로 사용하지 않는다.

```json
{
  "version": 1,
  "recordCount": 0,
  "recordSize": 0,
  "coordinateScale": 0,
  "snapshotDate": "YYYY-MM-DD"
}
```

## 6. 렌더링 계층

```text
Scene
├── Terrain
├── Water
├── Roads
├── District Boundaries
├── Buildings
│   └── InstancedMesh / Batches
├── Landmarks
├── Labels
└── Environment
    ├── Day
    ├── Sunset
    └── Night
```

## 7. 건물 렌더링

수십만 개 건물을 개별 heavyweight Mesh로 생성하지 않는다.

우선순위:

1. 공유 Geometry
2. 공유 Material
3. `InstancedMesh`
4. 거리 기반 표시 제한
5. Frustum Culling
6. 모바일 전용 표시 예산

## 8. 카메라 및 입력

지원 기능:

- 회전
- 확대
- 축소
- 패닝
- 자동 비행
- 자동 비행 후 수동 제어 복귀

모바일 입력은 한 손가락 회전, 두 손가락 확대/축소 및 이동을 기본 후보로 한다.

## 9. 랜드마크 자동 비행

14개 주요 랜드마크를 순차적으로 이동한다.

각 랜드마크 데이터:

- ID
- 이름
- 위치
- 카메라 위치
- 카메라 타깃
- 체류 시간

자동 비행 도중 카메라가 지형 또는 건물 내부로 들어가지 않도록 검증한다.

## 10. 환경 모드

- 낮
- 노을
- 야경

환경 전환 때문에 실제 지리 데이터가 변경되어서는 안 된다.

## 11. 모바일 렌더링 예산

조정 가능 항목:

- devicePixelRatio
- 그림자 해상도
- 그림자 사용 여부
- 가시 건물 수
- 원거리 geometry 단순화
- 환경 효과 수
- 라벨 밀도

## 12. 오류 처리

다음 오류는 식별 가능해야 한다.

- 건물 바이너리 로드 실패
- 메타데이터 불일치
- 지형 로드 실패
- 랜드마크 데이터 누락
- 자치구 데이터 누락

오류가 발생했는데 정상 데이터처럼 표시하지 않는다.
