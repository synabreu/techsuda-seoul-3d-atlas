# AGENTS.md — Seoul 3D Atlas 에이전트 작업 지침

## 1. 목적

이 저장소에서 작업하는 AI 에이전트는 `Seoul 3D Atlas`를 안정적으로 구현·검증·문서화·배포하는 것을 목표로 한다.

이 파일은 프로젝트 요구사항 전체를 담는 문서가 아니다. 에이전트가 이 저장소에서 작업할 때 따라야 할 **작업 방식, 검증 규칙, 금지사항, 완료 기준**을 정의한다.

세부 요구사항은 다음 문서를 따른다.

- `docs/product-spec.md`
- `docs/data-sources.md`
- `docs/rendering.md`
- `docs/validation.md`
- `docs/deployment.md`
- `ARCHITECTURE.md`

## 2. 최우선 원칙

1. 실제로 확인하지 않은 기능을 완료했다고 말하지 않는다.
2. 측정하지 않은 FPS, 메모리 사용량, 로딩 시간, GPU 사용량, 토큰 사용량을 추정해서 보고하지 않는다.
3. 존재하지 않는 데이터 출처, 라이선스, 스냅샷 날짜, 배포 URL을 만들어내지 않는다.
4. 시각적으로 그럴듯하다는 이유로 검증을 생략하지 않는다.
5. 기존 코드가 있다면 먼저 구조를 읽고 이해한 뒤 변경한다.
6. 동작 중인 기능은 명확한 이유 없이 전면 재작성하지 않는다.
7. 가능한 경우 수작업보다 재현 가능한 스크립트와 자동 검증을 우선한다.
8. 불확실한 부분은 가정으로 숨기지 말고 문서에 명시한다.

## 3. 작업 시작 절차

새 작업을 시작할 때 다음 순서로 확인한다.

1. `README.md`
2. `ARCHITECTURE.md`
3. `docs/product-spec.md`
4. 작업과 관련된 세부 문서
5. 기존 소스 구조
6. 빌드/테스트/검증 스크립트
7. 현재 데이터 파일 및 메타데이터

기존 구현을 이해하지 않고 바로 대규모 수정부터 시작하지 않는다.

## 4. 구현 원칙

### 제품 요구사항

제품 기능과 완료 기준은 `docs/product-spec.md`를 따른다.

### 데이터

데이터 출처와 라이선스는 `docs/data-sources.md`를 따른다.

다음 항목은 반드시 출처를 확인한다.

- 건물
- 도로
- 수계
- 서울 25개 자치구 경계
- 지형
- 랜드마크

### 렌더링

Three.js 기반 정적 웹사이트를 기본 구조로 한다.

대규모 건물 렌더링 시 다음을 우선 검토한다.

- 공유 Geometry
- 공유 Material
- `InstancedMesh`
- 배치 렌더링
- Frustum Culling
- LOD 또는 거리 기반 가시성 제어
- 모바일 전용 렌더링 예산

### 데이터 전처리

대규모 건물 데이터는 가능한 경우 압축 이진 형식으로 변환한다.

전처리는 다시 실행할 수 있어야 하며, 사용된 명령과 입력/출력 형식을 문서화한다.

## 5. 코드 변경 원칙

- 변경 범위를 최소화한다.
- 관련 없는 리팩터링을 한 번에 섞지 않는다.
- 숫자 상수에는 의미를 설명하는 이름 또는 주석을 사용한다.
- 데이터 변환 규칙은 코드와 문서가 서로 일치해야 한다.
- 빌드가 깨진 상태로 작업 완료를 선언하지 않는다.
- 렌더링 품질을 높이기 위해 성능 검증을 무시하지 않는다.
- 성능을 높이기 위해 데이터 정확성 또는 필수 기능을 임의로 제거하지 않는다.

## 6. 검증 원칙

최종 완료 전에는 `docs/validation.md`에 정의된 검증 항목을 실행한다.

최소 확인 항목:

- 서울 25개 자치구
- 처리된 총 건물 수
- 건물 이진 데이터와 메타데이터 일치 여부
- 회전
- 확대/축소
- 패닝
- 모바일 터치
- 14개 랜드마크 자동 비행
- 낮/노을/야경 모드
- 한강 가시성
- 주요 산악 지형 가시성
- 프로덕션 빌드

실행하지 않은 테스트는 `통과`로 기록하지 않는다.

## 7. 성능 보고 규칙

실제 측정이 없는 경우 구현한 최적화만 설명한다.

허용 예:
- 모바일에서 devicePixelRatio 상한을 낮췄다.
- 그림자 해상도를 줄였다.
- 원거리 건물 표시 수를 줄였다.

금지 예:
- “모바일에서 60 FPS를 달성했다.” — 실제 측정이 없다면 금지
- “로딩 속도가 40% 향상됐다.” — 비교 측정이 없다면 금지

성능 측정이 있다면 다음을 기록한다.

- 장치
- GPU
- 브라우저
- 해상도
- 테스트 장면
- 측정 방법

## 8. 배포 원칙

배포는 `docs/deployment.md`를 따른다.

OpenAI Sites 배포 기능이 실제 사용 가능한 경우:

1. 프로덕션 빌드 생성
2. 검증 통과 확인
3. OpenAI Sites 배포
4. 공개 URL 접속 확인
5. 핵심 기능 재확인
6. 실제 확인된 URL만 보고

배포 권한 또는 도구가 없다면 URL을 만들어내지 않는다.

## 9. 완료 보고

가능한 범위에서 다음을 보고한다.

### 빌드
- 빌드 성공/실패
- 산출물 위치
- 배포 성공/실패
- 검증된 공개 URL

### 데이터
- 총 처리 건물 수
- 자치구 수
- 랜드마크 수
- 데이터 스냅샷 날짜
- 주요 바이너리 파일 크기
- 바이너리 검증 결과

### 테스트
- 데스크톱 입력
- 모바일 입력
- 자치구 경계
- 자동 비행
- 낮/노을/야경
- 한강
- 지형
- 프로덕션 빌드
- 배포본

### 토큰
실행 환경이 정확한 토큰 사용량을 제공하는 경우에만 기록한다.

제공되지 않는 경우:

`토큰 사용량: 실행 환경에서 확인할 수 없음.`

### 남은 제한사항
미해결 문제를 숨기지 않고 기록한다.

## 10. 완료 정의

다음 조건을 만족해야 전체 프로젝트 완료를 선언할 수 있다.

- 프로덕션 빌드 성공
- 서울 25개 자치구 검증 완료
- 처리 건물 수 확인
- 건물 바이너리 검증 완료
- 핵심 데스크톱 조작 검증
- 핵심 모바일 조작 검증
- 14개 랜드마크 자동 비행 검증
- 낮/노을/야경 모드 검증
- 한강 및 주요 지형 시각 검증
- 데이터 출처와 라이선스 문서화
- 알려진 제한사항 문서화
- 배포 도구가 사용 가능하다면 OpenAI Sites 공개 배포 및 URL 검증

단순히 화면이 잘 보인다는 이유만으로 완료를 선언하지 않는다.
